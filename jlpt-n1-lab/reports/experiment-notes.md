# 试验中的发现

本文件记录方法上的观察；最新题目数量与检查状态以 `pilot-report.md`、`summary.json` 为准。

## 本地生成可运行，但正确率不能只看格式检查

在 M1 Max / 64GB Mac 上，已下载并运行 Qwen3.5 27B Q4_K_M 出题，使用 9B Q4_K_M 检查词汇填空和语法。所有推理请求发送到 `127.0.0.1:11434`。没有调用付费模型 API。本轮使用 `think=false`、6144 上下文及固定生成参数控制用时；结果不代表开启思考或更换模型后的质量上限。

原始三次试生成把目标「把握」变成选项「把握する」，且使用「理解する」「認識する」等可成立近义词作为干扰项。结构检查阻止了这三次结果入库。随后改成先给定词汇选项，再让模型编写语境。

给定选项仍不足以保证唯一答案，例如：

- 「現状を（　）する」可填「打開」或「認識」。
- 紧急情况需要「迅速な対応」也可能需要「柔軟な対応」。
- 「プロジェクトの進行を（　）にする」可填「円滑」或「迅速」。

部分句子也出现了漏助词或搭配不自然。比如「外部の電源依存しており」缺少「に」，「感情の抑制を失う」通常应改为「自制心を失う」或「感情の抑制が利かなくなる」。这些题目保留在候选区，并标出具体问题。

## 调整了读音校验方法

初期 9B 盲答出现过把「認識」误读为「ねんしき」、把「抑制」误读为「よくさい」的情况。词典所列读音分别是「にんしき」「よくせい」。因此：

- 读音正确项从底库读取，程序检查选项是否唯一及是否误用了底库中记录的合法异读。
- 读音题不再由模型决定答案。词典核对也不证明例句自然，需要另行检查。
- 模型仅继续检查词汇填空和语法：隐藏答案、翻译和知识点标签，要求列出所有能成立的选项。

早期还出现过“理由选对、数字索引报错”的情况。最终接口改为让模型返回选项原文，JSON Schema 将可返回文本限制在四个已给定选项中，再由程序映射到索引。结构检查通过的词汇/语法题按该接口重新检查（未通过者直接标记）；旧数字接口的原始响应仍保留作诊断记录。

`data/audits/` 与 `data/raw/` 中保留了早期读音盲答记录，作为调试证据；当前导出的读音题使用 `dictionary_check`，不会把那些旧模型判断当作有效结论。

另一个 9B 默认模型标签在本机使用 MLX 后端，试验时不支持结构化输出。尝试非约束 JSON 后也出现格式不稳定，最终更换为明确的 `qwen3.5:9b-q4_K_M` 标签。已移除这次试验下载的默认 MLX 模型；当前保留 27B、9B 的 Q4_K_M 模型。模型版本与摘要见 `environment.json`。

## 如何理解本次结果

1. **生成数量不是可用题数量。** 候选题必须经过筛选；格式、词典核对或模型盲答通过，都不等于内容已经正确。
2. **盲答通过率不是题目正确率。** 模型会误报，也会漏掉多解；同一家族的两个模型可能共同出错。内容抽查意见来自 Codex 主代理，不是日语教师或用户的人工认证。
3. **难度还未标定。** 一些题干较短、选项差异较大，适合词汇基础复习；不能据此声称达到正式 N1 真题强度，更不能换算考试分数。
4. **建议先使用审核通过的小题库。** 看题目是否帮助学习，再按已通过的题型扩充；有问题的知识点可附审核笔记重生成。

## 软件验证

已完成结构校验、选项随机化后答案及解析对齐、合法异读排除、旧审核失效、SQLite 保存、非法请求拒绝等自动测试。浏览器中使用独立测试副本验证了选择答案、展示解析、保存审核笔记、加入正式题库和退回后移除。测试副本的数据未写入正式学习记录。

桌面浏览器布局已检查。当前内置浏览器未实际应用请求的窄屏视口，因此没有把手机设备布局记为已验证。

## 六道修订样本

为实际验证改写流程，Codex 主代理修订了「配慮」「著しい」的填空、 「依存」「覆す」的读音例句，以及两道原本未在填空处考查「かたわら」的语法题。原稿和修订前的检查结果保存在 `data/revisions/`；每个修订稿带 `editorial_revision`，旧盲答与旧用户审核会因内容哈希变化自动失效。修订稿重新检查，仍留在候选区。其余疑点题保留，供后续比较和改写。
